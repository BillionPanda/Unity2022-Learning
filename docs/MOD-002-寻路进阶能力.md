# MOD-002 进阶 · AI Navigation 你可能还不知道的能力

> 依据：本机包 `com.unity.ai.navigation@1.1.7`（2025-06-26）的**包内官方文档**与 **8 个官方 Samples 场景**，逐条核对，不凭网上旧教程。
> 前提：你已经会基础的"点地面 → 角色走过去 → 绕开静态障碍"。下面全部是**超出基础**的部分。
> 对应 GP-10（游戏 AI）：这些能力正是"导航只是移动层，决策在别处"的具体体现。

---

## 先看全貌：这个包不止 `NavMeshSurface`

包里给你四个构建组件，多数人只用第一个：

| 组件 | 作用 | 你可能没用过 |
|---|---|---|
| `NavMeshSurface` | 为一类 Agent 烘焙一张 NavMesh | ✅ 会用 |
| `NavMeshLink` | 连接同一张或多张 NavMesh（含多层） | ⬜ 大概率没用 |
| `NavMeshModifier` | 按**层级**改烘焙时的区域类型 | ⬜ |
| `NavMeshModifierVolume` | 按**空间体积**改区域类型 | ⬜ |

外加 `NavMeshObstacle`（运行时动态障碍，包外内置模块）和 Off-Mesh Link 的自动生成。

## 能力 1：一个场景多套 NavMesh —— 不同体型的角色走不同的路

**大多数教程只教一个 Surface。但包内第一号示例场景就叫 `1_multiple_agent_sizes`。**

> **学完你能得到什么**
> - **能做出**：小兵能钻 1 米窄缝，坦克只能走大道；同一点下达目标，两者路径不同。
> - **能解释**：Agent Type 决定体素化与半径；不同 Surface 绑定不同 agentTypeID，互不干扰。
> - **能迁移**：RTS 多兵种、塔防不同尺寸敌人、NPC 与载具共存的地图。

**怎么做**：Project Settings → Navigation → Agents 里加第二个 Agent Type（比如把 Radius 从 0.5 改成 1.5）→ 在场景放两个 `NavMeshSurface`，各自选不同的 Agent Type → 分别 Bake → 给两个角色设对应 `NavMeshAgent.agentTypeIndex`。

**验收**：同一目标点，两个角色的行进路线肉眼可见不同；窄缝只有小兵能过。

## 能力 2：让角色"跳下去 / 翻过去" —— Link 与四种过桥动画

**基础导航只在平面上走。Off-Mesh Link 让它能跨越不在 NavMesh 上的空隙。**

> **学完你能得到什么**
> - **能做出**：角色从高台跳到地面、跨过沟渠、推开门再过去——而且跳跃动作由你控制，不是瞬移。
> - **能解释**：Link 是"图上的一条边"，连的是两个不相连的多边形；A\* 会把它的代价算进路径。
> - **能迁移**：多层地图、可破坏地形、门/梯子/传送点。

**怎么做（关键在 1.1 的新玩法）**：
1. 用两个空物体当 Start / End，挂 `NavMeshLink` 组件指向它们。
2. 把 `NavMeshAgent.autoTraverseOffMeshLink` 设为 `false`——这是关键开关，关掉后 Unity 不会自动瞬移。
3. 检测 `agent.isOnOffMeshLink`，拿到 `agent.currentOffMeshLinkData`，自己用协程把角色从 start 移到 end。
4. 跑完调 `agent.CompleteOffMeshLink()`。

**官方 Samples 已给四种现成实现**（`AgentLinkMover.cs`）：`Teleport` / `NormalSpeed` / `Parabola`（抛物线跳跃）/ `Curve`（AnimationCurve 自定义轨迹）。直接抄 Parabola 那份就能用。

**验收**：角色跳沟时有抛物线弧线，落地后继续正常寻路；不是"啪"地闪过去。

**你可能不知道的新能力**：`NavMeshSurface` 从 1.1.0 起**能自动生成 Link**（`generate links` 选项），不用手动摆。还有 `Jump` 这个内置 Area Type 专门分配给自动生成的 Link。对应包内示例场景 `8_heightmesh` 与文档 `BuildingOffMeshLinksAutomatically`（在线版）。

## 能力 3：HeightMesh —— 让角色贴着台阶走，而不是走在"斜坡近似"上

**这是最容易被忽略、但视觉差异最大的一个。**

> **学完你能得到什么**
> - **能做出**：角色在台阶上一级一级踩上去，而不是沿着一条被"抹平"的斜面滑上去。
> - **能解释**：NavMesh 是可走空间的**近似**（台阶被压成斜坡），HeightMesh 保存精确高度数据用于落脚；代价是烘焙变慢、运行时占内存。
> - **能迁移**：有楼梯/坡道的室内场景、对脚步贴合要求高的第三人称游戏。

**怎么做**：`NavMeshSurface` 的 Bake 设置里勾选 **Height Mesh**，重新烘焙。对比开/关两版角色在台阶上的脚部位置，截图留证。

**验收**：能说清"NavMesh 管找路，HeightMesh 管落脚高度"这个分工，并有对比截图。

## 能力 4：动态障碍的两种模式 —— 会"挖洞"的和只会"躲"的

**很多人以为 `NavMeshObstacle` 就是个会动的墙，其实它有两种完全不同的行为。**

> **学完你能得到什么**
> - **能做出**：推箱子堵住路口后，NPC 会**重新规划绕路**，而不是撞在箱子上卡死。
> - **能解释**：`Carve` 打开时障碍在 NavMesh 上挖洞；移动时洞怎么更新，由 `Carve Only Stationary` 与 `Move Threshold` 决定；关掉 Carve 只有短距离的碰撞规避。
> - **能迁移**：可推动箱子、爆炸后出现的残骸、移动的平台/车辆。

**怎么做**：给一个 Cube 加 `NavMeshObstacle` → 打开 `Carve` → 角色走向它的另一侧 → 把它拖到路中间 → 看角色是否改道。再对比关掉 `Carve` 时的行为。

**验收**：能说清"默认 Carve Only Stationary 为什么性能好"，以及一帧延迟的存在（官方文档明确写了 NavMesh 查询结果比障碍变化晚一帧）。

## 能力 5：区域代价与 Area Mask —— 让角色"能走但不愿走"，或"根本不许走"

**这是从"能寻路"到"会决策"的关键一步，也是 GP-10 书单里 AI 知识在 Unity 的落点。**

> **学完你能得到什么**
> - **能做出**：两条路都能到终点，一条近但要蹚水（慢），一条远但走平地 → 角色按你设的代价选；再把某扇门只给"人类"走，僵尸走不了。
> - **能解释**：A\* 的代价是 `距离 × 区域代价`；代价必须 > 1；Area Mask 是位掩码，决定某类 Agent 能不能用某区域。重叠区域一般取最高索引，但 `Not Walkable` 永远优先。
> - **能迁移**：恐惧/危险区域规避、地形偏好、角色权限通行。

**怎么做**：
1. Navigation 窗口 → Areas 标签 → 自定义一个 `Water` 区域（29 个自定义槽位可用），设代价 3.0。
2. 用 `NavMeshModifier` 把水面标记为 Water（按层级）或用 `NavMeshModifierVolume` 框一块区域（按空间）。
3. 角色 A 的 Area Mask 包含 Water，角色 B 不包含 → 看两者路径差异。
4. 运行时用 `NavMeshAgent.SetAreaCost()` 临时改代价，比较改前改后。

**验收**：能演示"能走但不选"和"完全不能走"两种不同效果，并解释它们分别由 cost 和 mask 控制。

## 能力 6：运行时烘焙与增量更新 —— 程序化地图的必需品

**静态场景 bake 一次就够了。但程序化生成 / 可破坏地形，必须在运行时重建。**

> **学完你能得到什么**
> - **能做出**：按下键在运行时生成一段新地板，NavMesh 自动更新，角色立刻能走上去；删除地板后路径跟着变。
> - **能解释**：`BuildNavMesh()`（全量重建）vs `UpdateNavMesh(existingData)`（增量更新）的区别；异步版本返回 `AsyncOperation`，可避免一帧卡顿。
> - **能迁移**：Roguelike 地牢、可破坏场景、玩家建造系统。

**怎么做**：包内 Samples 给了三套现成方案，按场景挑一套抄：
- `DynamicNavMeshObject.cs` —— 动态实例化物体时请求全局更新
- `GloballyUpdatedNavMeshSurface.cs` —— 一个静态标志位聚合多物体请求，每帧最多更新一次
- `MeshTool.cs` —— 网格被修改后用 `AsyncOperation` 异步更新（最值得学，避免卡顿）

示例场景：`2_drop_plank`（动态木板）、`4_sliding_window_infinite` / `5_sliding_window_terrain`（无限滚动地图）、`6_modify_mesh`（实时改网格）、`7_dungeon`（程序化地牢）。

**验收**：能在运行时改地形后，角色立即按新地形寻路；用 Profiler 观察同步与异步更新的帧时间差异。

## 能力 7：多个 Surface 的连接与叠加加载

**大地图切块、多场景叠加时，NavMesh 不是"一张大网"而是多张网拼起来。**

> **学完你能得到什么**
> - **能做出**：两块分开的地板各自烘焙，用 `NavMeshLink`（segment-to-segment）把它们连起来，角色能跨块走过去。
> - **能解释**：多 Surface 之间不会自动连通，必须显式 Link；叠加加载场景时的 NavMesh 数据与 GUID 关系。
> - **能迁移**：开放世界分块、流式加载关卡、多人共享地图。

**怎么做**：直接导入包内示例 **"Build And Connect NavMesh Surfaces"**（Package Manager → AI Navigation → Samples），场景 `1_multiple_agent_sizes` 与 Link 相关部分就是照着做的。这个示例本身就是官方给的教学案例。

**验收**：角色能跨过多张 Surface 到达目标；删掉 Link 后走不过去——前后对比就是证据。

## 能力 8：动画与导航解耦 —— 角色朝向不被路径强行拧过去

> **学完你能得到什么**
> - **能做出**：角色转身有平滑过渡，或在移动时播放受击/瞄准动画，而不是被 NavMeshAgent 每帧硬设朝向。
> - **能解释**：`updateRotation`、`angularSpeed`、`autoTraverseOffMeshLink` 这些开关各自把哪部分控制权还给动画层。
> - **能迁移**：第三人称角色、战斗中的移动、过场动画混合。

**怎么做**：把 `NavMeshAgent.updateRotation` 关掉，用 Animator 或代码根据速度方向自己设朝向；读包内文档 `CouplingAnimationAndNavigation.md` 与 `NavHowTos.md`（含源码）。

**验收**：角色朝向由动画/代码控制且能正常到达目标。

## 优先级建议（如果只做三件）

| 顺序 | 能力 | 为什么先做 |
|---|---|---|
| 1 | **能力 3 HeightMesh** | 一个勾选框就能看到明显视觉差异，性价比最高 |

## 依据与边界

- 本机包版本 **1.1.7**；1.1.6 起最低支持 Unity 2022.3 LTS，你的 2022.3.14f1c1 满足。
- 所有能力描述来自包内 `Documentation~` 与 `Samples~` 一手文件；`BuildingOffMeshLinksAutomatically.md` 在本机包中未随附，文档里的链接指向在线版，如需细读以在线文档为准。
- 包内 Samples 在 Package Manager 里点 "Import into Project" 即可导入，不用从 GitHub 下载——符合你的网络条件。
- 本文件只讲"有什么能力/怎么验"，不替你决定做不做。每个能力的"验收"就是你自己判定是否学会的标尺。
