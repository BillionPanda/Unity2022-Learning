## 设计约定（重要）

1. **每个场景完全自包含**：一个目录 = 一个 `.unity` 场景 + 一份专属脚本 + 一份 README + 各自 `.meta`。
   场景之间**不共享脚本、不共享材质、不共享 Prefab**——删掉任一目录不影响其他场景。
2. **场景文件本身很薄**：只含相机、灯光、一个挂专属脚本的 Bootstrap 对象。
   台阶、障碍、Agent、NavMeshSurface/Link/Modifier 等**全部由该场景的脚本在 `Awake()` 中搭建**。
   好处是场景 YAML 不含复杂组件序列化，不容易因为手写而引用丢失；打开点 Play 即完整呈现。
3. **每个脚本顶部有 `// @trace MOD-002`**，自检脚本按目录统计完整性（见下方命令）。
4. 交互统一用 `OnGUI` 显示状态，不依赖 UI Toolkit / 额外字体资源。

## 8 个场景与学完预期

| # | 目录 / 场景 | 你要亲手观察的现象 | 学完你能回答 |
|---|---|---|---|
| 01 | `01_HeightMesh` / `HeightMeshDemo` | 按 H 前后，角色在台阶上从"滑斜坡"变"一级级踩"，脚部 Y 读数变化 | 为什么 NavMesh 是近似、HeightMesh 管精确落脚；代价是什么 |
| 02 | `02_AgentSizes` / `AgentSizesDemo` | 同一点下达目标，绿色小兵钻 1m 窄缝，橙色坦克绕宽道 | Agent Type 如何决定体素化与半径；多兵种地图怎么建 |
| 03 | `03_OffMeshLink` / `OffMeshLinkDemo` | 角色跨沟时走抛物线弧线；按 J 切回瞬移对比 | Link 是图上的一条边；`autoTraverseOffMeshLink` 为什么是关键开关 |
| 04 | `04_ObstacleCarving` / `ObstacleCarvingDemo` | 空格把箱子推到门口，角色重新规划；C 切换 Carve 对比 | Carve 挖洞 vs 短距规避；`Carve Only Stationary` 的性能意义 |
| 05 | `05_AreaCost` / `AreaCostDemo` | 绿角色蹚短路水域，蓝角色绕远路；按 C 改代价后绿角色改道 | 能走但不愿走（cost）与根本不许走（mask）是两件事 |
| 06 | `06_RuntimeBake` / `RuntimeBakeDemo` | 空格铺板 → 重建导航 → 角色立刻过桥；再按移除 | 全量 `BuildNavMesh()` 与增量 `UpdateNavMesh(data)` 的区别 |
| 07 | `07_MultipleSurfaces` / `MultipleSurfacesDemo` | 两张 Surface 默认不连通；按 L 断开 Link 后角色到不了对岸 | 分块地图/叠加加载为什么必须显式 Link |
| 08 | `08_AnimationDecouple` / `AnimationDecoupleDemo` | 橙色指示块展示朝向；按 R 对比平滑转身 vs 硬拧向 | 为什么第三人称/受击动画必须关 `updateRotation` |

**建议动手顺序**：01 → 03 → 05 → 02 → 其余。前三个视觉差异最大、性价比最高；02 依赖下面的项目级设置。
